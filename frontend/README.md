# Fortress Frontend

React / TypeScript / Vite / Tailwind / TanStack Query / Dropzone. Основной запуск вместе с настоящим backend: [LOCAL_SETUP](../docs/LOCAL_SETUP.md). Native API раздаёт production build на одном origin; модель отображается как обученный, но не валидированный прототип. Ниже — отдельные dev/test команды; synthetic demo не подменяет анализ пользовательских видео.

## Подготовка и проверки

Node >=22.12; проверено на Node 22.22.2, npm 11.1.0. Из каталога frontend своего checkout:

```powershell
npm ci --ignore-scripts --no-fund --no-audit --registry=https://registry.npmjs.org
npm run typecheck
npm test
npm run build
```

Все версии закреплены package-lock.json. Установка требует доступа к npm; приложение/сборка используют локальные зависимости без CDN. Офлайн-изоляция рабочего сервиса проверяется профильными задачами инфраструктуры.

## Работа с настоящим API

```powershell
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Открыть http://127.0.0.1:5173. Vite проксирует /api на http://127.0.0.1:8000; запуск и конфигурация backend принадлежат №1/I. Без работающего backend будет видимая ошибка связи, без обученного совместимого release — model_not_ready и инструкция импорта. Точные команды импорта публикует backend/ML; UI не запускает train и не подставляет прогнозы.

Пользователь вводит существующий API-ключ в форме. Ключ живёт только в памяти вкладки и передаётся X-API-Key. Не задавайте его через VITE_*, URL, .env, localStorage/sessionStorage или исходники. После закрытия/перезагрузки требуется повторный ввод. Сброс отменяет fetch/polling и освобождает Blob URL. Принятое сервером задание этим не отменяется.

Производственная сборка — dist/. Проверить только статический результат можно `npm run preview -- --port 4173`; это не запускает backend. При развёртывании /api и protected media маршруты нужно направить на API того же origin согласно infra. У Vite preview нет настроенного API proxy; для браузерных dev-проверок с backend используйте npm run dev. Остановка локальных dev/preview серверов — Ctrl+C в запустившем их терминале.

## Явный synthetic test/demo

```powershell
npm run dev:fixture -- --host 127.0.0.1 --port 5173 --strictPort
```

Используйте отдельный свободный порт или остановите предыдущий Vite. Введите произвольное тестовое обозначение вместо настоящего ключа. Показано уведомление «Деморежим: показаны примеры результатов, загруженные видео не анализируются»; readiness остаётся untrained/not validated. Транспорт использует искусственные примеры contracts/fixtures.json: 202, processing, затем synthetic violation с декодируемым тестовым JPEG 16×16. Сценарии `?demo=clean` и `?demo=error` показывают no_violation и failed. Параметры работают только в явном dev:fixture.

Выбранный MP4/MOV в fixture mode остаётся в памяти mock transport и доступен плееру через имитацию защищённого preview; файл не отправляется на сервер и не анализируется. Это позволяет проверить управление настоящим HTML video. Искусственные события, кадры, длительность анализа и выводы не являются результатом обработки выбранного ролика; их происхождение явно указано. Длительность строки файла берётся из его настоящих локальных metadata. После перезагрузки тестовые файлы недоступны. Проверка backend preview, PTS/VFR/rotation и реального API остаётся U.

Fixtures подключаются только guarded dynamic import при Vite mode fixture. `vite build --mode fixture` запрещён. Production build не содержит fixture payload/transport, а сетевая ошибка не переключает на demo. Компонентные тесты используют отдельный transport с явным происхождением данных.

## Поведение

- Каждый ролик: непустой MP4/MOV до 200 МиБ. На экране также указаны 180 с, обе ориентации 1920×1080/1080×1920 и 60 fps. Декодирование и фактические лимиты проверяет сервер; каждый запрос передаёт один файл.
- Fetch не даёт надёжный byte upload progress: передача indeterminate, отдельно от processing; подтверждение приёма — только корректный 202 и UUID. Неопределённый исход POST не повторяется автоматически. Уточняйте состояние по известному ID, а не повторной загрузкой.
- Polling выполняет GET, максимум два повтора при сетевой ошибке; останавливается на done/failed, ошибке и unmount. Ручная повторная проверка не создаёт новое задание. ID хранится в памяти; сохраните его вручную для возврата после закрытия вкладки. Возврат требует ключа.
- 400/401/404/413/415/429/503 и network различимы; 401 освобождает сессию для повторного ввода. Ошибки не показывают raw exception/внутренние пути. Неизвестное состояние не превращается в done/failed.
- JSON проверяется offline схемами K. Jury JSON не расширяется UI-полями. Diagnostics отображаются отдельно, только для того же job_id и текущего public status.
- Защищённый fetch media/preview создаёт Blob URL; фактический поток ограничен не более чем 200 МиБ, даже без Content-Length. URL освобождаются при смене задания/ключа/unmount. Ключ отсутствует в URL; редиректы запрещены.
- По K/A3 preview сохраняет elapsed source time `(PTS-originPTS)*time_base`; seek передаёт точные исходные секунды. Нет расчёта frame_index/fps. Компонентный seek не доказывает VFR/rotation/nonzeroPTS browser correctness: это U после I.
- Событие показывает 1–3 JPEG с исходными timestamp. Unknown, unsupported, partial coverage, source verification, revision и версии остаются видимыми. Пустой список не обещает абсолютной безопасности. K не задаёт связь violation→finding ID: источник не приписывается событию по позиции в массиве; findings и источники показаны отдельно.

## Граница проверки

Компонентные и клиентские тесты проверяют поведение React/Query/client на явных K fixtures и отказах транспорта. Обновлённый UI проверен в браузере при 360/768/1440 px: очередь, настройки, ошибки, synthetic результаты и отсутствие событий. На сгенерированных MP4 проверены локальная длительность, превью и переходы настоящего HTML video по таймлайну. Это авторская проверка frontend; настоящее API, внешний HTTPS, корректность backend PTS/VFR/rotation и ML readiness не объявляются пройденными. U выполняется только после принятого I.

## Настоящий API в изолированном test profile (для I/U)

```powershell
npm run dev:api-test -- --host 127.0.0.1 --port 5173 --strictPort
```

Этот режим использует настоящий fetch через /api proxy, без frontend fixture transport. На странице видна метка SYNTHETIC API TEST. Выбирайте только искусственные видеопримеры. Для разрешения тестового upload сервер обязан сам сообщить `test_only=true`, `trained=false`, `validated=false`; обычный production not_ready этим режимом не обходится. Компоненты проверки backend и изолированные PostgreSQL/Redis готовятся по backend/README.md в I/U. Production остаётся защищённым trained/validated gate.

Режим только для dev: `vite build --mode api-test` запрещён, как и fixture build. Стандартный production build игнорирует test/demo props; это проверено отдельным тестом. Реальный test-profile API в браузере пока не запускался, зависимость I не принята. Этот запуск не называется ML validation.

## Очередь видео

Загрузка и очередь объединены в один рабочий раздел на всю ширину. Компактная верхняя панель сохраняет FORTRESS, основные действия используют бордовый Forte. Общие Button, StatusBadge, VideoFile и Notification задают единые кнопки, статусы с текстом/иконкой, строки файлов и сообщения. Учтены видимый фокус, prefers-reduced-motion и контраст текста.

API-ключ, модель и поиск задания по ID находятся в боковой панели «Настройки», скрытой по умолчанию. Native dialog исключает фон из навигации, удерживает фокус, закрывается кнопкой/Escape/нажатием на фон и возвращает фокус к кнопке. Закрытие сохраняет ключ, очередь и polling в памяти вкладки. Ответ 401 очищает сессию и открывает настройки. Если запуск заблокирован, причина и действие открытия настроек находятся возле очереди.

Зона загрузки поддерживает выбор нескольких файлов, drag/drop и вставку из буфера. Большая зона показывается только для пустого списка; после добавления файлов сворачивается в строку «Добавить ещё видео» с теми же действиями. В пустом состоянии краткие лимиты видны сразу; в компактной мобильной версии они перенесены в «Требования к файлам». Разрешение и fps также доступны по раскрытию. Ошибка выбора содержит имя файла, причину и способ исправления. Файлы можно добавить до ввода ключа; отправка начинается после «Начать анализ», авторизации и проверки модели.

Очередь состоит из строк с превью, именем, длительностью, размером, статусом и удалением ожидающего файла. В ней остаются ожидающие, передаваемые, обрабатываемые и неподтверждённые записи. Done/failed переходят в результаты без дублирования; полностью завершённая очередь скрывается. На телефоне подписи и действия переносятся без горизонтального переполнения. Счётчики показывают оставшиеся файлы и завершённые done/failed; запуск содержит число ожидающих файлов. «Очистить очередь» удаляет только незавершённые локальные записи при отсутствии активной обработки, «Очистить результаты» — только done/failed. Эти действия не отменяют серверные задания. После очистки всего списка возвращается большая зона загрузки.

Браузер читает настоящие metadata выбранного File и создаёт JPEG-превью локально, без сетевой отправки. Пробы отменяются при удалении/reset/unmount, Blob URL освобождаются. При недоступных metadata или декодировании показаны «Длительность не определена» и нейтральная заглушка превью. Нет вымышленных значений; для восстановленного задания без File допускается duration_sec собственного diagnostics, размер/превью при отсутствии явно недоступны. Локальная длительность имеет приоритет над длительностью диагностики.

API допускает одно незавершённое задание. Следующий POST выполняется только после done/failed предыдущего. Пауза удерживает следующие файлы; принятое задание продолжает опрашиваться. Ожидающие записи можно убрать. При 429/503, разрыве polling или неопределённом исходе POST очередь приостанавливается. Неопределённый POST и прерванная передача автоматически не повторяются; неизвестный приём не изображается отменой. Готовность модели можно повторно проверить после импорта без удаления ожидающих файлов.

Текущий файл и общий прогресс считаются по завершённым файлам очереди. Передача fetch отображается без выдуманного процента; измеримый прогресс анализа появляется только при наличии processed_sec/duration_sec от того же задания. Остальные этапы имеют неопределённый индикатор. «Не закрывайте вкладку» показано только пока остались локальные ожидающие/передаваемые файлы. Ошибки и неподтверждённый приём не считаются готовыми результатами.

До 20 записей в очереди, каждый файл — до 200 МиБ. Очередь и файлы живут только в памяти вкладки. Закрытие/перезагрузка страницы удаляет ожидающие файлы; reset ключа очищает очередь и результаты. Серверные задания этим не отменяются, их можно открыть по сохранённому ID. File-ссылка после подтверждённого приёма освобождается; результаты загружаются защищённым API. У браузерной очереди нет отдельного серверного persistence или отмены worker.

Под очередью всегда есть отдельный раздел результатов. До завершения показано пустое состояние; после — превью и имя слева, число событий непосредственно под именем, «Открыть результат» справа. Пока очередь требует запуска, основное бордовое действие — запуск; после завершения — открытие результата. Параметры файлов, уведомление demo, требования и вспомогательные сообщения увеличены до 14 px. Ошибка с причиной и следующим действием, неизвестное число событий и «Возможные нарушения не обнаружены» различаются. Просмотр открывается явным действием; готовый результат ИИ обозначен «Возможное нарушение». На широком экране плеер и события находятся в двух колонках, на узком — вертикально. Возврат к списку восстанавливает фокус на выбранном результате.

Материалы для презентации без тестовых цветовых полос: [presentation/README.md](presentation/README.md). Сцена искусственная и не содержит людей/клиентских данных; production приложение не подменяет ей превью выбранных файлов.

## Таймлайн и нормативные основания

Кнопка результата переводит к просмотру выбранного видео. Под проигрывателем есть шкала времени, точки событий и интервалы срабатывания правил; остальные проверки свёрнуты. Маркеры, интервалы и range с клавиатуры отправляют точные source seconds в VideoPlayer. Текущее время и длительность обновляются по media events; до metadata используется duration_sec только того же задания. Выходящие за длительность точки не рисуются как допустимые; неверный интервал не запускает seek. Без длительности остаются текстовые таймкоды.

Для каждого правила показаны интервал, объяснение, вид источника, статья/пункт (source.section), редакция, проверенность, безопасная HTTP(S)-ссылка и ограничения. Triggered вынесены наружу; остальные правила доступны в раскрываемом блоке. Связь violation→finding не выводится по порядку/совпадению времени; основания относятся к своим интервалам правил.

Прочитан исходный «Кейс_ForteBank.docx»: разделы 4 и 6 требуют название документа, пункт/раздел, ссылку и связь с фрагментом. Конкретных законов исходный кейс не перечисляет. Текущий K не передаёт название документа и явный идентификатор связи события с правилом; эти пробелы видны в UI. В текущем rules/sources/index.json нет проверенного нормативного источника. Фронтенд не назначает закон сам и не выдаёт неизвестное основание за подтверждённое нарушение. Заполнение проверенных источников и расширение общего контракта остаются отдельной backend/rules зависимостью.
