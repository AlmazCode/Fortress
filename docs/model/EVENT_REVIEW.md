# Исправление событий в локальном сервисе

Продолжение: [новые головы и контекст описаний](SOURCE_ACTIONS.md), версия `source-action-review-v2`. Историческое исправление выбора исходного кадра ниже сохранено; новые метрики действий приведены отдельно от75% классификации роликов.

Следующий этап обучения выполнен: [подробные действия и слабые сценарные интервалы](TEMPORAL_EVENT_TRAINING.md). Малые новые варианты/DINOv2/VLM не превзошли контроль. Затем [фиксированный ансамбль](SEED_VOTE.md) улучшил clip accuracy до75% и выбран для прототипа; action/state головы для карточек остались прежними. Метрики ниже относятся к историческому исправлению API/UI с одиночным контролем.

Версия обработки: `source-action-review-v1`. Модель, веса, порог и прежний grouped benchmark не меняются. Это исправление API/UI, а не новое обучение или повышение accuracy.

В предыдущем native API кадр выбирался по максимуму нескольких несвязанных оценок (`safe_open`, сумка, чашка). Для первого development-видео это давало 1,5 с, хотя работа с плоским предметом была распознана моделью на 20–25,5 с. Такой кадр не объяснял вердикт.

Теперь API проверяет интервалы `candidate_events` по исходным PTS, временам и оценкам соответствующего действия. Положительный clip verdict показывает до четырёх фрагментов для проверки; обычные действия не объявляются доказанными нарушениями. У каждого фрагмента есть название, интервал и до трёх настоящих JPEG: середина, начало, конец. Опорное время — существующий sampled source frame около середины интервала. Если положительный вердикт нечем локализовать, задание получает `failed/insufficient_evidence`, без выдуманного таймкода.

Все интервалы действий и состояний, включая отрицательные по clip verdict ролики, передаются в diagnostics timeline и доступны в UI с переходом по времени. Наблюдения имеют `state=unreviewed`, `known_mask=false`; `findings=[]`. Оценки не выдаются за калиброванные вероятности. При большом числе кандидатов карточки ограничены по стоимости декодирования и распределены по длительности видео; полный список интервалов сохранён в diagnostics.

В production inference нет чтения разметки, поиска по имени/хешу известного видео или подстановки ожидаемых секунд. Хеш используется только для проверки целостности входа. Прежние завершённые результаты не переписываются: для исправленного результата загрузите видео заново.

## Что показала проверка

- Первый MOV: три модельных интервала — работа с плоским предметом 6–15 с, настольное устройство 14–17 с, работа с плоским предметом 20–25,5 с. Для последнего исходный опорный кадр — **22,5 с**; это середина кандидатного действия, а не доказанное начало подмены денег.
- Реальный HTTP upload→done на отдельном native-сервере: первый положительный MOV **24,82 с**, отрицательный контроль **15,90 с**; девять исходных JPEG для трёх карточек и пустой список alerts для отрицательного ролика. Оба результата содержат timeline observations.
- На шести заранее перечисленных development-видео среднее время самой модели **5,34 с**. Загрузка модели/файла, кадры и preview в это время не входят. Это не SLA и не независимый тест accuracy.
- Python: `pytest tests/local tests/contracts -q` — **74 passed**. Frontend: **143 tests**, typecheck/build — exit 0. Проверены чужие PTS, несогласованные границы, кадры вне интервала, сохранение поздних событий при лимите карточек, отрицательный результат без ложных alerts, нейтральное отображение обычных действий и передача `insufficient_evidence` из настоящего дочернего процесса.

Подробные приватные результаты, исходные кадры, сырые прогнозы и протокол проверки сохраняются в `%LOCALAPPDATA%\Fortress\verification\event-check-v1`. Видео, кадры, ключи и веса в Git не добавлены.

## Что остаётся сделать для событийной модели

Текущие головы распознают общие действия и состояния. В их taxonomy нет отдельного обученного класса «подмена денег», номинала, передающего/получающего участника или подтверждённой блокировки ОС. Подробные импортированные сценарные действия в `prepared/actions.json` имеют неполную/непросмотренную разметку; текущий исследовательский этап обучался на отдельной разметке общих действий. Наличие подробного сценария в JSON не означает, что именно эти классы обучались.

Новые temporal-этапы уже проверены в [отчёте обучения](TEMPORAL_EVENT_TRAINING.md), но не прошли gates качества. Дальнейшая предметная разметка/обучение должны отдельно проверять приём, пересчёт, повторную работу с купюрами, выдачу, открытие/закрытие сейфа, взятие/размещение сумки и правила над последовательностью. Сравнивать по отложенным семействам и метрикам событий: precision/recall, ложные тревоги на видео, overlap интервалов и ошибка таймкода. Визуально неразличимые номиналы/OS-state оставлять unknown.75% ансамбля — метрика clip verdict, не точность локализации;80%/95% не достигнуты.
