# Распознавание действий и контекст описаний

Новый пакет `source-actions-v1` сохраняет бинарный ансамбль **75,00% (27/36)** и заменяет только прошедшие проверку визуальные головы. Общая цель80% не достигнута. Для семи динамических классов macro F1 с учётом недоступной записи на бумаге — **42,27% вместо42,13%**. Высокое качество определения присутствия людей не включается в эту среднюю метрику действий.

## Что улучшилось

Четыре прежних outer-разбиения по семействам,36 development-источников. Известные цели сравниваются на одних исходных PTS; unknown игнорируется, недоступные положительные классы считаются пропусками. Пороги и параметры выбираются на внутренних разбиениях. Повторное исследование этих видео и выбор прошедших gates классов не являются независимой приёмкой.

| Класс | Метод | Precision | Recall | F1 прежде → теперь |
| --- | --- | ---: | ---: | ---: |
| Работа с компьютером | Временная калибровка прежней головы | 90,74% | 73,13% | 80,00 →80,99% |
| Сотрудник у рабочего места | Линейная голова поверх DINOv2 | 98,70% | 98,70% | 95,19 →98,70% |
| Человек у стойки | Линейная голова поверх DINOv2 | 99,32% | 96,89% | 80,50 →98,09% |

Для работы с компьютером TP49/FP5/FN18 вместо50/8/17. Это уменьшение ложных положительных кадров ценой одного дополнительного пропуска, а не рост recall или доказательство проведения банковской операции. Параметры финального исполнения: max3 по соседним исходным кадрам, порог0,9655900597572327; пороги отдельных outer folds выбирались независимо на своих внутренних разбиениях.

Головы сумки, открытого сейфа, экранов и остальных действий сохранены от контроля: новые варианты не прошли gate P≥0,8/R≥0,5/F1≥0,8 и улучшение над сопоставимым контролем. Нельзя выдавать метрики трёх выбранных классов за80% качества всех действий или нарушений. Сумка, контакт с настольным устройством и сейфом остаются главными провалами. Для записи на бумаге и двух людей у стойки есть лишь по4 положительных проверенных кадра в одном семействе; отсутствие устойчивого обучения явно отражено в отчёте.

## Обучение и отрицательные результаты

`ml.action_kernel` проверяет RBF-признаки по временным DINOv2-векторам. Первый запуск остановлен проверкой coverage: старый агрегат контроля использовал другую ревизию целей для четырёх классов. Fold-предсказания и `failed.json` сохранены. Ни проверка, ни исходные протоколы не отключались.

Новый `ml.action_linear` сравнивает обе модели с сохранёнными исходными OOF-предсказаниями контроля на одинаковых целях. Линейный вариант целиком дал macro F1 динамических действий36,52% и отклонён как общая замена. Прошли только две головы присутствия. LBFGS-предупреждения первого kernel-запуска сохранены; линейные readouts используют liblinear и прекращают fit при несходимости.

`ml.action_calibration` выбирает identity/median3/mean3/max3 и порог только по внутренним OOF-предсказаниям уже обученных голов с точным составом train. Завершённые старые fits не переобучаются и не перезаписываются. Прошла голова компьютера; остальные изменения движений рук/сумки/сейфа отклонены. Приоритет сборки зафиксирован: принятый linear, затем kernel, затем calibration, иначе control; выбора лучшего варианта по outer-F1 нет.

Дополнительный `ml.action_rare` разрешил одному положительному семейству обучать редкую голову сумки/сейфа: прежнее требование двух семейств делало часть внутренних голов недоступными. Этот вариант проверен новым протоколом на тех же outer folds с прежним gate качества. Доступность выросла, распознавание не улучшилось до gate; ни один из трёх классов не подключён. Отрицательные результаты сохранены, пороги подключения не снижались.

DINOv2 ViT-S/14 заморожен, Apache2.0; исходники `facebookresearch/dinov2`, commit `7764ea0f912e53c92e82eb78a2a1631e92725fc8`, веса SHA `b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9`. Два вида392×392, CLS+2×2 patch pools,3840 признаков на исходный кадр,2fps. Дообучаются только малые головы. Новых исходных видео нет; загрузки пользователей не используются для обучения.

Протоколы, SHA отчётов, положительные/отрицательные кадры и все метрики: [SOURCE_ACTIONS_RESULTS.json](SOURCE_ACTIONS_RESULTS.json). Полные артефакты вне Git: `FortressArtifacts/training-ready/dino-source-actions-v1`, `dino-linear-actions-v1`, `source-action-calibration-v1`.

## Описание событий

`source-action-review-v2` добавляет контекст по тем же исходным кадрам события. Открытый сейф/сумка на столе/светящийся экран при распознанном сотруднике не описываются как оставленные без присмотра. Unknown,NaN и промежуточная оценка присутствия не становятся отсутствием. Подсказка об уходе требует предыдущего присутствия и непрерывного интервала предполагаемого отсутствия не менее2с; она остаётся гипотезой для проверки.

Манипуляции с сумкой сами по себе не означают размещения на столе или оставления. Пересекающиеся действия показываются как отдельные предположения. Светящийся экран не доказывает отсутствие блокировки ОС; содержимое сумки, запирание сейфа, подмена/номинал денег и проведение операции не выдумываются. Карточки нейтральные, findings пустые, наблюдения unreviewed, нормативная применимость unknown.

На исходных кадрах дополнительно просмотрены удерживание сумки014/20–24с, сейф008/21,5–25,5с, экран004/31–35с и настольное устройство039/25–29с. Приватные контактные листы/PTS/SHA и заметки сохранены в `action-source-review-v3`; human_approved=false. Эти заметки не объявлены новой обучающей разметкой и не растягиваются на непросмотренные интервалы.

## Пакет и воспроизведение

Пакет111111326байт, identity `bcefb403110e075fd841869df18421a327f091a569dcd31a7c79c48cf7638faf`. Внутри исходный `seed_vote/`, линейные головы, DINOv2 с локальными исходниками/лицензией/весами, протоколы и OOF-доказательства. Сеть при inference не нужна; тренировочные кэши не нужны. Проверяются все файлы и пересчитываются метрики из упакованных OOF. Порог0,5 отображаемой оценки соответствует выбранному внутреннему порогу головы; оценка не является вероятностью.

```powershell
.venv\Scripts\python.exe -B -m ml.action_kernel prepare --root D:\FortressData\training-ready --output D:\Runs\actions-kernel
.venv\Scripts\python.exe -B -m ml.action_kernel run --output D:\Runs\actions-kernel
```

Первый run исторически остановится coverage guard при прежних ревизиях целей. Следующие независимые протоколы используют сохранённые fold-предсказания, не меняя его код:

```powershell
.venv\Scripts\python.exe -B -m ml.action_linear prepare --parent D:\Runs\actions-kernel --output D:\Runs\actions-linear
.venv\Scripts\python.exe -B -m ml.action_linear run --output D:\Runs\actions-linear
.venv\Scripts\python.exe -B -m ml.action_calibration prepare --parent D:\Runs\actions-kernel --output D:\Runs\actions-calibration
.venv\Scripts\python.exe -B -m ml.action_calibration run --output D:\Runs\actions-calibration
.venv\Scripts\python.exe -B -m ml.source_action_infer --experiment D:\Runs\actions-linear --calibration D:\Runs\actions-calibration --seed-bundle D:\Models\seed-vote-v1 --output D:\Models\source-actions-v1
```

GPU-подготовка признаков выполняется при удержании общего `runtime/gpu.lock` сервиса. CPU readouts могут обучаться без GPU. Для переключения остановите idle-сервис, выберите пакет через `tools/select_local_model.ps1`, запустите `tools/start_local.ps1 -Background`. Прежний `seed-vote-v1` остаётся для возврата. Старые done-результаты не переписываются: загрузите ролик заново.
