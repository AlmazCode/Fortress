# Эксперименты на имеющихся видео

Пользователь разрешил следующий этап реального локального обучения 18 октября
2026 года. Он не требует новых видео и не снимает требований к production release.
Код: `python -m ml.small_data --help`. Это отдельный экспериментальный классификатор
вердикта; backend продолжает требовать полноценный проверенный событийный release.

## Протокол

Из 40 уникальных источников используются только 36 исходных train/dev видео,
16 семейств сценариев. Четыре прежних test видео и оба их семейства остаются
зарезервированными. Два исходных файла-дубликата не становятся новыми наблюдениями.
Оригинальные разметка, split, видео и первый baseline сохраняются.

`prepare` до обучения фиксирует хэши данных и исполняемого кода, четыре внешних
grouped folds, по три внутренних folds, ограниченный набор конфигураций и seeds
42/137/2026. В одном fold семья и исходник не пересекают train/validation;
обе части должны содержать оба класса. Неудачный split отвергается.

Для каждой внешней обучающей части параметры и порог выбираются исключительно
по внутренним OOF ответам seed42: balanced accuracy, macro-F1, затем меньшая BCE.
Нормализация кадров и масштабирование видео-признаков обучаются на train текущего
fit. Внешняя validation не выбирает веса, эпохи, порог или семейство модели.
Дополнительные seeds используют тот же выбранный порог и показывают чувствительность
к инициализации; лучший seed не выбирается. Внешние OOF ответы каждой модели
показываются отдельно. Оценка процедуры выбора семейства использует только выбор
семейства внутри внутренних folds, а не победителя по внешним ответам.

После сравнения тот же внутренний протокол выбирает конфигурацию на всех 36
development видео. Финальная одиночная модель всегда имеет заранее назначенный
seed42. `frozen_decision.json` связывает fit, порог и SHA до тестового предсказания.
`evaluate-reserved` запускается отдельно после завершения и не перезаписывает
существующий диагностический отчёт. Этот старый внутренний test уже наблюдался:
новой независимой проверкой он не является.

Все эти результаты — исследовательская оценка на одной камере. Уже просмотренный
датасет, малое число семей и последовательные эксперименты ограничивают выводы.
95% на неизвестных ракурсах этот протокол не подтверждает.

## Сравниваемые модели

| Вариант | Что обучается |
| --- | --- |
| `linear` | L2 logistic regression на mean/max текущих 576D признаков; обе нормализации только по train |
| `gru` | GRU 576→256 и голова вердикта, две заранее заданные конфигурации |
| `mil` | Голова коротких окон: 8 кадров/4 секунды, шаг 4 кадра/2 секунды; mean/max и изменение признаков; log-mean-exp по окнам |
| `finetune` | Сначала GRU, затем последние два блока того же MobileNet и GRU; ранний CNN prefix и BatchNorm statistics заморожены |

MIL обучается меткой всей видеосумки. Ни одному отдельному окну не присваивается
метка нарушения из метки ролика. Её оконные оценки не являются проверенной
локализацией, типом нарушения или юридическим доказательством.

GRU и fine-tuning ограничены 64 временными позициями на видео: равномерная выборка
при оценке, сохраняющий порядок jitter внутри временных корзин при fine-tuning.
Это покрывает длительность ролика, но может пропустить короткое действие.
MIL и linear используют все исходные 2fps признаки. Сравнение содержит различия
в представлении и вычислительном бюджете; это не утверждение их эквивалентности.

Для fine-tuning кэшируются активации замороженного `features[:-2]` каждого вида.
У него нет обучаемых статистик и доступа к меткам. Сохраняются 2fps, source PTS,
тот же encoder, три вида и версии исходной подготовки. Проверяется восстановление
старых признаков. Группировка свёрток по видам и кадрам совпадает с исходной:
изменение размера CUDA batch способно изменить округление TF32.

Варианты яркости 0.85/1.15 и временной jitter используются исключительно во время
обучения; оценка получает исходную яркость и фиксированные позиции. Нет разворота
времени, удаления решающего эпизода с переносом положительной метки или подсчёта
аугментаций как независимых роликов. Градиенты whole-video objective накапливаются
микробатчами до трёх видео, чтобы ограничить GPU activation memory.

## Запуск

В проверенном worktree с установленным extra `ml-cuda`, из корня репозитория:

```powershell
$artifactRoot = 'D:\FortressArtifacts\training-ready'
$experiment = Join-Path $artifactRoot 'small-data-v2'
$weights = Join-Path $artifactRoot 'weights\mobilenet_v3_small-047dcff4.pth'
$weightsSha = '047dcff4addef86ea5bc2eff13c9614dc11f47ab1160d0a71a25e7db994f4e1f'
python -m ml.small_data prepare --cache "$artifactRoot\cache-three_crop" --output $experiment --audit-report "$artifactRoot\benchmark-all42-20261018\report.json"
python -m ml.small_data run --experiment $experiment --encoder-weights $weights --encoder-sha256 $weightsSha --device cuda
python -m ml.small_data evaluate-reserved --experiment $experiment --encoder-weights $weights --encoder-sha256 $weightsSha --device cuda
python -m ml.small_data infer --experiment $experiment --video 'D:\videos\sample.mov' --encoder-weights $weights --encoder-sha256 $weightsSha --device cuda
```

`prepare` требует новый каталог. Повтор `run` после прерывания повторно использует
завершённые fits с той же identity; незавершённый fit обучается с начала. Optimizer
resume внутри отдельного fit не заявляется. Завершённый эксперимент не перезапускается.
Код/данные/протокол должны совпадать по SHA; после их изменения нужен новый каталог.
Для воспроизведения старого эксперимента используйте его точный source commit.

Fingerprint новых протоколов нормализует переводы строк и проверяет AST обучающего
кода и три зависимости. Исправления CLI/декодирования отделены от обучения. Для уже
выполненного протокола с байтовым fingerprint требуется его `source_snapshot.zip`:
loader сначала проверяет архив по исходному fingerprint, затем сравнивает обучающий
AST и зависимости с текущими. Архив не исполняется и не извлекается. Изменение
модели, нормализации, sampling или сетки параметров не считается совместимым.

`review_tasks.json` содержит 12 ошибок первого baseline на train и четыре конфликта
меток, 15 уникальных заданий с пересечениями. Это черновая очередь проверки,
`human_approved=false`, а не исправленная gold-разметка. Существующие неполные
интервалы действий и кадры без меток не становятся отрицательными примерами.
Оценки по исходным меткам организатора считаются отдельно; обучение сохраняет
явно выбранную ранее политику `user_scenario`.

Результаты, изображения, fits, веса и отчёты с метками хранятся вне Git. В репозиторий
попадают код, проверки и агрегированные наблюдения. Облачная обработка, звук и
распознавание лиц не используются.

## Фактический результат первого раунда

Обучающий код: `6aea1a7382250f4e4d289c630c8a786a864de747`.
Исправление inference CLI: `6ae685b641d3c9e0baa29fcf8ab485199c20bdd2`.
Протокол: `978ce5adc92c6ab8056ca611af645fa14670cfdce2d35315b228a1c94f8e920e`.
Выполнены **184 fit**, четыре outer folds, три inner folds и три seeds.

Результаты на 36 development видео, каждый OOF ответ получен без обучения
на семействе соответствующего видео. Основной seed42 задан до расчётов:

| Вариант | Accuracy seed42 | Balanced accuracy seed42 | Macro-F1 seed42 | Accuracy по трём seeds |
| --- | ---: | ---: | ---: | ---: |
| Linear | 47.22% | 50.33% | 47.18% | 47.22% |
| GRU | 50.00% | 54.18% | 50.00% | 47.22–55.56% |
| MIL | 55.56% | 56.86% | 55.00% | 52.78–58.33% |
| Fine-tuning | 55.56% | 56.86% | 55.00% | 52.78–61.11% |

Вложенная процедура выбора семейства получила accuracy50%, balanced accuracy54.18%,
macro-F1 50% на основном seed. Разброс и малое число групп не подтверждают95%.
С прежними66.7% на смеси train/dev/test эти результаты напрямую не сравниваются.

Внутренняя процедура на всех development выбрала исследовательский linear C=1,
порог0.9980914. После фиксации решения старый test дал2/4 (50%) против3/4 первого
baseline. Кандидат **не заменил baseline** и не активирован в приложении.
При фиксированном выбранном пороге он имеет50% на всей подборке42; порог после
test не менялся. Отдельная диагностическая проверка порога0.5 на его обучающих
36 видео даёт36/36: это запоминание доступного набора, не успешный бенчмарк.
Перенос порога из внутренних folds также оказался неустойчивым.

Проверки: **27 tests passed**, без skips; strict manifest regression, grouped/inner
boundaries, norm-only-train, реальные fits и suffix gradients, fingerprint guards.
Все36 замороженных prefix кэшей восстановили исходные признаки с max delta0;
source PTS совпали. Два raw MOV (train и test) дали точно те же scores, что cache;
отдельный `python -m ml.small_data infer` прошёл. Это проверка вычислительного пути,
а не доказательство правильного вердикта. В первом прерванном протоколе batch-layout
guard сработал до первого fit; результаты сохранены отдельно, не подмешаны.

Полные локальные `cv_report.json`, `RESULTS.json`, `comparison.csv`,
`oof_predictions.csv`, `final_all42.csv` и15 preview sheets находятся в каталоге
эксперимента `small-data-v2` вне Git. Агрегаты: [SMALL_DATA_RESULTS.json](SMALL_DATA_RESULTS.json).
Ни одна метка не исправлялась по ответу модели или по желаемому проценту.

Следующий обоснованный этап на тех же исходниках — проверка временных эпизодов и
обучение распознавания наблюдаемых действий/состояний с использованием имеющейся
объектной разметки. Текущие video-level эксперименты такой событийной модели не

разбора, а не автоматического превращения в точные положительные/отрицательные интервалы.
