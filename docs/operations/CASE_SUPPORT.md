# C01–C15: границы поддержки

Текущий исходный кейс уже прочитан: юрисдикция РК установлена, нормативы нужно находить самостоятельно. Для Windows-сервиса добавлен [отдельный адаптер НБРК №231](RK_RULES.md),п.12/19/20/22, с проверенным текстом и неизвестной применимостью к конкретному эпизоду. Таблица ниже фиксирует прежний engine C01–C15; его статусы не объявляются проверенными recognizers задним числом.

Версия `cases.v1-draft`. Все 15 маршрутов сохранены в `rules/packs/cases.v1.json` с предпосылками, объектами/состояниями, интервалами, исключениями, ограничениями и путями тестов. Поля `action_classes` пусты: маршруты не превращены в выдуманные action IDs.

| Маршруты | Технический шаблон | Нормативная поддержка |
| --- | --- | --- |
| C01 пачка; C02 документ; C10 пересчёт до хранения; C12 повторная обработка купюр | prerequisite | unsupported / legal unknown |
| C04 оставленные ценности; C05 хранилище; C15 приборы после смены | unresolved-state | unsupported / legal unknown |
| C03 партии; C11 без клиента | cross-session | unsupported / legal unknown |
| C06 ключ; C07 документы/печати; C13 личные вещи; C14 сосуд/питьё | presence | unsupported / legal unknown |
| C08 экран после ухода; C09 дверь/вход | response | unsupported / legal unknown |

Первоначальная причина блокировки — отсутствие исходного кейса и проверенных источников — относится к прежнему этапу. Сейчас нормы найдены, но для строгого engine C01–C15 по-прежнему не подтверждены recognizers, применимость и исключения всех маршрутов. Открытые инфраструктурные документы из PREFLIGHT.md не являются нормативными источниками кассовых правил.

Текущий engine возвращает для каждого маршрута `unknown`, `support=unsupported`, `source.verified=false`. Это не отсутствие нарушений. Положительные/сложные отрицательные synthetic проверки пяти общих шаблонов относятся только к программной логике, не к ML и не к законности конкретного кейса.

Для включения маршрута необходимы фактический первоисточник/исходный кейс, проверка применимости и исключений, локальный текст с SHA-256/редакцией/датой, проверенные recognizers и явные actor/party links. Для absence дополнительно нужны полный существенный интервал, видимость, конец этапа и альтернативы. До этого юридическая приёмка остаётся **blocked/unknown**.

Сумма, подделка, системная проводка, OS lock, полномочия и содержимое непрозрачной сумки не выводятся по отсутствующим данным. Деньги на столе, касание ПК, светлый кадр и уход не запускают правило сами по себе.
