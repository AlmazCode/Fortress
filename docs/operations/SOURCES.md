# Источники правил и критерий достаточности

Источник достаточен для нормативного правила только если реально открыт исходный применимый документ, установлены юрисдикция, редакция, точный раздел, область действия и исключения; локальный текст/хэш, дата получения, URL и source_kind сохранены. Похожая норма другой юрисдикции не заменяет недостающий исходный кейс.

## Текущий реестр

`rules/sources/index.json` содержит единственный `provided-case-brief` с `source_kind=unverified`, `normative=false`, `verified=false`. Это нормализованная сводка маршрутов из предоставленного ТЗ, **не дословная копия оригинального кейса и не нормативный документ**. `snapshots.jsonl` хранит её текст и SHA-256 UTF-8 content; тест проверяет этот хэш. Совпадение хэша не доказывает нормативную силу или подлинность отсутствующего оригинала.

Нормативные URL для C01–C15 не предоставлены и не открыты; jurisdiction/revision/applicability/exceptions неизвестны. Юридических названий нарушений, фиктивных URL и чужих редакций в pack нет. `normative_source_id=null` у всех маршрутов. Открытые при O1 Docker/NVIDIA/WSL/RFC документы перечислены в PREFLIGHT.md; они не используются как нормы кассовых операций.

Конкретный внешний пробел: владелец должен предоставить оригинальный кейс и юрисдикцию, а также открытый первоисточник либо разрешённую локальную политику с редакцией и исключениями. До этого бесконечный поиск похожих банковских правил не закрывает ни один acceptance; он не выполнялся. Следующий поиск начинается только с этого конкретного материала и вопроса применимости C01–C15, с сохранением реально открытых URL/выводов.

## Дальнейшая проверка источника

Для применимого источника реестр должен содержать verified/normative, source_kind `official` либо `internal_policy`, URL, revision, retrieved_at_utc, applicability `confirmed`, exceptions_reviewed и snapshot_path. Engine проверяет, что путь остаётся внутри checkout и SHA-256 фактических байтов локальной копии совпадает. Summary snapshot в JSONL не используется для подтверждённого нормативного source. Новая редакция требует новой rules version и повторного прогона затронутых кейсов.

Объяснение каждого rule finding следует порядку **факт → признак возможного несоответствия → источник → ограничение**. Версия правил и источник доступны в diagnostics; source frames/timecodes создаёт pipeline из оригинала, engine не рисует JPEG и не приписывает подлинные кадры шаблону.
