# Проверка плана и перехода на GitHub

Дата: 17 октября 2026 года. Проверяется пакет документов, не готовность приложения.

## Что сверено

Исходник — опубликованный экспорт `bc139562beb1d4bdf306669a4cd7bdfd6332a62c`, происходящий от согласованной базы `46b7bc941e64fec5649242b8290607c8f7339819`. Все четыре новых личных ТЗ пользователя содержат по две одинаковые копии заданий; каждый task title, description, files, acceptance и depends сопоставлен с экспортом. Хэши приложений и результаты сверки сохранены в `PROVENANCE.json`; личные аккаунты и исходные вставки не публикуются.

Сохраняются 36 уникальных задач, 48 прямых зависимостей, исполнители №1/№2/№3/№4 с 9/6/12/9 задачами и две независимые стартовые задачи K/O1. Валидатор проверяет циклы, лишние транзитивные связи, одновременное владение одними файлами у независимых разных разработчиков, полноту четырёх ТЗ и локальные ссылки. Точные числа файлов и критериев — в `AUDIT.json`.

## Исправленные противоречия

- Общие документы, корневой AGENTS.md и каждое личное ТЗ теперь явно говорят: Aster больше не управляет исполнением. Старые launch/claims/listener/heartbeat/submit вызовы исключены из рабочего процесса. Старые отчёты не становятся GitHub-статусами автоматически.
- В активных описаниях удалён исторический административный абзац «Сейчас только план…». Исходный экспорт сохранён отдельно в `archive/`, его нельзя исполнять как новую инструкцию.
- В личных инструкциях всех четырёх участников указан automatic-all. Устаревшие административные окончания двух критериев заменены: E, критерий 7 — «manual review сохраняется» на фактическую GitHub-проверку commit/отчёта; Z, критерий 1 — «по manual policy» на фактическую проверку точных commits/критериев. Остальной текст этих критериев и все остальные продуктовые критерии сохранены. Точные before/after находятся в `plan.json → migration.coordinationChanges`. Нормативная применимость и человеческая разметка от этого не считаются подтверждёнными.
- Устаревшая схема из 12 крупных этапов в продуктовом ТЗ заменена действующими 36 этапами; ID, прямые depends и file scopes не изменены.
- У каждого участника свой журнал. №1 ведёт общую сводку и интеграцию, чтобы четыре разработчика не перезаписывали один status-файл.
- Исходная база используется для проверки происхождения; дальнейшая работа учитывает принятый контракт и зависимости по точным SHA. Открытый PR или push не закрывает зависимость сам по себе.
- Документы больше не утверждают, что папка не закоммичена/не опубликована. Публикация пакета идёт отдельной веткой `codex/github-transition`; основная ветка и чужие worktree этим изменением не обновляются.

## Воспроизведение проверки

Из корня checkout:

```sh
python docs/github-plan/validate_plan.py
git diff --check
```

Для намеренного изменения пакета сначала обновить данные/документы, затем выполнить `python docs/github-plan/validate_plan.py --refresh` и обычную проверку. Manifest хранит SHA-256 всех файлов пакета и корневых инструкций с нормализацией CRLF→LF для одинаковой проверки на Windows/Linux. Это не подпись и не доказательство выполнения приложения.

Дополнительно проверен сам валидатор на изолированных временных копиях: искусственный цикл зависимостей, изменение критерия, возвращение обязательного Aster и смена владельца отклонены с exit code 1. Копия пакета с Windows CRLF прошла проверку с exit code 0. В исходном пакете валидатор и `git diff --check` завершились с exit code 0.

## Что остаётся непроверенным

Реализация задач первоначально `unverified`: миграция не утверждает, что получены и проверены commits других разработчиков. Прежние активные чаты автоматически не остановлены и новые не запущены. Эти инструкции не рассылались другим чатам.

Доступность Docker/GPU/CUDA, runtime isolation/volumes, trusted внешний HTTPS, реальные API/browser/recovery checks, применимые первоисточники норм, видео/разметка и trained release данным аудитом не проверялись. Они остаются критериями соответствующих задач. Отсутствие настоящего release даёт `model_not_ready`, а не готовый анализ; полный train/независимая ML-оценка остаются отложены.

Внешние технические страницы из исходного ТЗ при переносе повторно не открывались; ссылки сохранены как источник требований. Работа над приложением по этой документационной задаче не запускалась.
