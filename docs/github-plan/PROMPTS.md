# Промпты для четырёх чатов

Эти тексты пользователь отправляет после решения перейти на GitHub. Они не были отправлены автоматически. Предыдущие остановленные чаты сами не продолжатся.

## №1 — Главный / Backend

```text
Работаем над https://github.com/AlmazCode/Fortress через GitHub/Git, без Aster MCP. Я запускаю разработчика №1 (Главный / Backend). Прочитай docs/github-plan/README.md, PLAN.md, REQUIREMENTS.md и DEV1_BACKEND.md. Твои taskIds: K, A1, A2, A3, A4, A5, A, I, Z.
Сначала проверь точный репозиторий и текущие ветки/коммиты/PR: уже выполненное не переделывай. Сохрани незакоммиченные изменения и checkpoint, работай в своей отдельной ветке/worktree с префиксом codex/, не создавай вложенную test/demo-папку. MCP-регистрация и ожидание запуска больше не нужны. Следуй зависимостям и действующему контракту. Реально проверяй каждый результат и продолжай к следующей своей готовой задаче без вопросов на каждый переход. Веди только свой docs/github-plan/status/DEV-1.md.
Разрешаю обычные локальные коммиты, push своей рабочей ветки и PR только в этом репозитории. Не делай force-push, не удаляй чужие ветки и не публикуй сервис/данные/секреты. Чаты и сабагентов не создавай без отдельного разрешения. Полное обучение не запускать: оставить инструкции для другого ПК. Если исчерпан лимит или обязательный блокер не позволяет работать, сохрани результат и честно укажи, что требуется; не объявляй проект завершённым.
Ты главный: сначала включи подготовленную папку docs/github-plan в отдельную ветку и опубликуй её обычным PR, чтобы остальные могли получить тот же план. После реальных проверок разрешаю объединять PR в этом репозитории через штатный GitHub merge при прохождении обязательных проверок и соблюдении защиты веток. Сначала K, затем своё направление; интегрируй результаты остальных, выполни финальные проверки и передай путь, команду запуска, отчёт и известные ограничения.
```
